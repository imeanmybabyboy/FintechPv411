Solidity - мова описання смарт-контрактів.
Смарт-контракт -- вузол у мережі, з яким можлива 
взаємодія інших вузлів (смарт-контрактів, облікових записів)

Взаємодія -- запуск методів, а також очікування подій.

Файл починається з ліцензійного ідентифікатора.
Оскільки всі смарт-контракти є відкритими, неможливо
приховати якісь алгоритми, питання їх ліцензування 
набуває високої актуальності. Ідентифікатор зазначається
коментарем у першому рядку коду (SPDX - System Package Data Exchange)
// SPDX-License-Identifier: MIT
Якщо ліцензії немає або автор не зазначає обмежень, то 
вживається спеціальний ідентифікатор UNLICENSED
// SPDX-License-Identifier: UNLICENSED

pragma solidity ^0.8.28;
Версія визначає можливості (фічі) компілятора для оброблення файлу. 
Директива діє на даний файл, якщо підключаються інші файли, то 
кожен може мати свої обмеження. Обмеження файлу не поширюються на 
обмеження підключених файлів. 

Модульність - підключення додаткових файлів. 
Діють принципи JavaScript (ES-6) - підключення як модулів.
Передбачені наступні форми підключення модулів або їх частин:
import "filename"
import * as symbolName from "filename"
import "filename" as symbolName
import {name1, name2 as n2} from "filename"

Типи даних, типізація.
Як означення (3GL), тип даних - це певна інформація про
- розмір даних, що зберігається
- правило перетворення вихідних даних у бінарні і навпаки
   1 (16 біт) -- 00000001 00000000
- перелік допустимих операцій
= з появою CTS (4GL) тип даних - об'єкт, що визначає перелік дозволених
   складових частин як-то методи, поля, конструктори, властивості тощо
Product p = new PC();  p.getCard() ?  virtual->PC.getCard() non-virtual->Product.getCard()

Типізація:
- строга (сувора) - відсутнє неявне перетворення типів
- статична - тип змінних не модифікується під час роботи програми
- динамічна - змінна може набути іншого типу при роботі програми 

Solidity:
- типізація статична, сувора 
- система типів - 3GL 

Розрізнення Value/Reference типів: присутнє
Value типи завжди розміщуються у стеку і не вимагають додаткових модифікаторів
...returns (uint)
Reference типи можуть мати різне розміщення
 - storage - постійне сховище, що зберігає результати між запусками методів
 - transient storage - сховище, що зберігається протягом транзакції, потім видаляється
 - memory - зберігається протягом одного виклику.
Спосіб збереження впливає на вартість виконання функції.
За замовчанням - найдорожчий storage, тому якщо постійне збереження не 
вимагається, слід додавати модифікатори memory чи transient
...returns (string memory)

Логічний тип bool
Цілі типи поділяються на знакові та беззнакові різного бітового розміру
знакові: int8...int256, int==int256
беззнакові: uint8...uint256, uint==uint256
Логічні операції: x||y, x&&y, !x
Бітові операції: x|y, x&y, ~x, x^y, бітові зсуви: x<<y, x>>y
(не плутати: бінарні операції, у протилежність унарним, це ті, що 
мають два операнди)
Бітові операції виконуються над кожним бітом операнду(ів) і мають цілий результат
Логічні операції виконуються над логічним типом і мають логічний результат
0 & 1 = 0 :          0 | 1 = 1 :           ~1 =  254 (uint8) / -2 (int8) 
      00000000           00000000           00000001 
      00000001           00000001           ---------~ 
      --------&          --------|          11111110 (254 / -2)  
      00000000           00000001            

true && false = false    true || false = true   !true = false


10 & 5 = 0           10 | 5 = 15 (0x0F)
     00001010           00001010    
     00000101           00000101    
     --------&          --------|   
     00000000           00001111    

!! бітові операції найшвидші, "рідні" для процесора, у десятки-сотню разів
швидші за арифметичні операції.
Корисні приклади:
= перевірка парності - класично (x % 2 == 0) в основі операція ділення
  та пошуку залишку (%); бітовий варіант - (x & 1 == 0)
= множення на 2 - (x << 1), на 4 - (x << 2), на 8 - (x << 3)...
= ділення (цілочисельне) на 2 - (x >> 1), на 4 - (x >> 2), на 8 - (x >> 3)...
= відокремлення байт-значення: (x & 0xFF) - все, що більше за 255 буде занулено

Арифметичні операції традиційні, є піднесення до ступеня (x ** y) з 
обмеженням y > 0. При діленні тип зберігається, до дробового не переводиться.
Округлення завжди здійснюється у бік нуля:
 5 / 2 = 2
 -5 / 2 = -2

Числа з фіксованою точкою - зберігають точність в межах заданої кількості цифр.
(числа з плаваючою точкою можуть округлюватись, порушуючи математичну рівність)
Їх принцип збереження - окремими цифрами (замість перетворення у бінарну систему)
fixed / ufixed
fixedMxN M - загальна кількість біт для збереження даних, N - кількість 
дробових цифр. fixed = fixed128x18, 18 цифр після коми відповідає діленню 
1 ETH на складові частини.

Адреса - особливий  тип даних для представлення адрес у мережі. 
Обсяг - 160 біт, подається як 0x(40 HEX digits) -- 42 символи.
